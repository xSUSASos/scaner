# Этапы: что сделано и почему

Каждый раздел — что делает код, ключевые параметры и на что они влияют, как проверить.

---

## Общие решения

- **Углы в долях [0..1]**, а не в пикселях (`core/geometry.py`). Одни и те же углы годятся для превью 1600 px и для оригинала 50 Мп.
- **Страница — рецепт** (`core/page.py`): путь + углы + фильтр + поворот. Картинка всегда строится заново `render()`: превью — на уменьшенной копии, экспорт — на оригинале (`render_full`). Правки не накапливают потерь.
- **Размеры ядер фильтров — относительные** (доля стороны). Иначе превью и финал выглядели бы по-разному.
- `opencv-python-headless` вместо `opencv-python`: обычная сборка тащит свой Qt, который конфликтует с PySide6.

## Этап 1. Загрузка и автодетект — `core/imageio.py`, `core/detect.py`

**Загрузка.** `np.fromfile` → `cv2.imdecode` (кириллица в пути). Флаг `IMREAD_IGNORE_ORIENTATION` + ручной поворот по EXIF-тегу 0x0112 (`apply_exif_orientation`, 8 вариантов) — поведение явное и одинаковое для всех форматов. HEIC — через `pillow-heif` (OpenCV его не знает). Сохранение: `cv2.imencode` + `tofile`.

**Детекция** (на копии 800 px — быстро и не зависит от разрешения):

| Шаг | Параметр | Влияние |
|---|---|---|
| GaussianBlur | `blur_ksize=5` | больше — меньше краёв от текста/шума, но размываются углы листа |
| Canny, пороги от медианы | `canny_sigma=0.33` | больше — больше краёв (и мусора); авто-пороги работают и на тёмных, и на светлых фото |
| Морф. закрытие | `close_ksize=5` | склеивает разрывы контура листа |
| convexHull + approxPolyDP | `approx_eps=0.02…0.05` | перебор точности, пока не получится 4 вершины; оболочка убирает «вмятины» от пальцев |
| фильтр площади | `min_area_ratio=0.15` | меньшие 4-угольники — не документ |

**Кандидаты и выбор (v1.1, после первого реального фото).** Первая версия брала «самый большой 4-угольник» — на тетрадном листе на пёстром фоне, где угол листа закрыт обложкой, контур листа разрывался, слипался с фоном, и побеждал кривой контур. Теперь три стратегии только *предлагают* кандидатов:

1. контуры Canny (как выше);
2. порог Оцу (светлый лист на тёмном фоне);
3. **прямые Хафа** (`HoughLines`): до 8 сильнейших почти-горизонтальных и почти-вертикальных прямых, все пары «верх/низ» × «лево/право», углы — пересечения. Работает при разорванном контуре и закрытом угле.

Побеждает кандидат с лучшей **оценкой = опора × контраст × площадь^0.25**:
- *опора* — доля периметра на краях Canny (расширенных на 2 px);
- *контраст* — разница «цвета фона» в полосах по обе стороны каждой стороны (ΔE в Lab; яркость — 80-й перцентиль, чтобы чернила не мешали; полоса шириной ~5% кадра, чтобы захватить несколько строк). Строка текста внутри листа: бумага | бумага → контраст ≈ 0; край листа: бумага | фон → 1. Стороны объединяются геометрическим средним — одна фальшивая сторона роняет всю оценку;
- *площадь^0.25* — при равенстве предпочитаем весь лист, а не таблицу на нём.

**Две карты краёв (v1.1.1).** Пороги Canny «от медианы» на светлом столе получаются высокими (медиана 194 → 130/255), и слабый край «бумага → светлый фон» теряется. Поэтому строится вторая, «мягкая» карта с потолком порогов 60/120: она только *добавляет кандидатов* (`canny-soft`, `hough-soft`), а оценка по-прежнему идёт по первой карте — на пёстром фоне лишние края текста и клетки не влияют на выбор. Простое понижение порогов ломало реальное фото тетради (ошибка 16% кадра). Тест светлого фона теперь гоняется на 5 разных листах: раньше он проходил на одном «удачном».

Опора считается для всех кандидатов (сотни у Хафа), контраст — только для 25 лучших. `min_score=0.35`: ниже — рамка по краям, `found=False`. Время: ~0,3 с на кадр.

**Проверка:** `pytest tests/test_imageio.py tests/test_detect.py` — наклон, тень, ромб 45°, светлый фон, разные разрешения, шум (→ рамка), пёстрый фон с закрытым углом (регрессия реального фото; старая логика ошибалась на 79% кадра).

## Этап 2. Перспектива — `core/geometry.py`

- `order_points`: сортировка по углу `atan2` вокруг центра (обход по часовой), старт с min(x+y). Классический «min/max по x+y и y−x» ломается на листе, повёрнутом на ~45°.
- `output_size`: ширина = max(верх, низ), высота = max(лево, право), +1 пиксель. Максимум — чтобы не терять разрешение на дальней (укороченной) стороне.
- `getPerspectiveTransform` → матрица 3×3; `warpPerspective` с `BORDER_REPLICATE` (без чёрной каймы).
- Ограничение: при сильном наклоне камеры пропорции листа восстанавливаются приблизительно (для точного нужна фокусная длина).

**Проверка:** `pytest tests/test_geometry.py` — все 24 перестановки углов, повёрнутый прямоугольник, «туда-обратно» перспектива.

## Этап 3. Фильтры — `core/filters.py`

- **Магия цвета**: фон = морф. закрытие (заливает текст бумагой) + сильное размытие, на копии 512 px → растянуть. `img / фон * 255` убирает тени, цвета сохраняются. Затем `255-(255-v)*1.4` (текст темнее, белое остаётся белым) и unsharp mask (`sharpen=0.6`).
- **Ч/Б**: `adaptiveThreshold(MEAN_C)`. `bw_block_percent` (окно, % стороны): меньше — лучше держит неравномерный свет, но «съедает» жирные линии; `bw_c`: больше — чище фон, тоньше текст. MEAN_C, а не GAUSSIAN_C: среднее по окну — O(1) на пиксель при любом окне (на 50 Мп это доли секунды).
- **Серый**: одноканальный результат (PDF/PNG меньше).
- **Яркость/контраст**: LUT на 256 значений; контраст — наклон вокруг 127.5.
- **Поворот**: `cv2.rotate` на 90°·k по часовой.

**Проверка:** `pytest tests/test_filters.py` — тень убрана, красный сохранён, Ч/Б одинаков на превью и ×3.

## Этап 4. CLI — `cli.py`

```
python cli.py samples\*.jpg -o out --filter magic --debug
```
С `--debug` сохраняются `_1_edges_*.png` (карта краёв), `_2_contour.jpg` (найденный контур: зелёный — найден, красный — рамка), `_3_warped.jpg`. Если на вашем фото контур не нашёлся — смотрите карту краёв: разрывы → увеличить `close_ksize`; много мусора → уменьшить `canny_sigma` / увеличить `blur_ksize` (`DetectParams` в `core/detect.py`).

Замер на синтетике 50 Мп: детекция 0,08 с; финальный рендер 0,05–0,3 с; превью 4–30 мс.

## Этап 5–6. GUI и многостраничность — `ui/`

| Файл | Что делает |
|---|---|
| `workers.py` | `run_task(fn, …)` — функция в отдельном `QThread`; результат/ошибка/прогресс приходят сигналами в GUI-поток |
| `document_model.py` | `Document`: упорядоченные страницы, у каждой превью ~1600 px и мини-копия ~300 px для миниатюр |
| `corner_editor.py` | превью + 4 угла; лупа ×3 с перекрестьем при перетаскивании; углы не выходят за кадр; «Авто», «Весь кадр» |
| `filter_panel.py` | 4 режима, яркость/контраст, для Ч/Б — окно и C; поворот ±90° |
| `result_view.py` | `PreviewRenderer` — живое превью результата |
| `page_list.py` | миниатюры, перестановка drag&drop, удаление (Del/кнопка), выбор = повторная правка |
| `ocr_dialog.py` | текст OCR: копировать / сохранить .txt |
| `main_window.py` | раскладка, меню, drag&drop файлов, очередь загрузки, экспорт/OCR с прогрессом и отменой |

**Потоки.** Воркер никогда не трогает виджеты. Его сигналы принимает объект `Task`, живущий в GUI-потоке, — Qt доставляет их через очередь событий (QueuedConnection). Пока поток работает, ссылка на `Task` хранится в `_active`, иначе сборщик мусора уничтожит работающий QThread и программа упадёт. В воркер всегда уходит `page.clone()` — GUI может менять страницу, пока идёт рендер.

**Живое превью.** Рендер — по превью (мс), не по оригиналу. Одновременно идёт не больше одного рендера; запросы не чаще раза в 100 мс, побеждает последний; счётчик поколений отбрасывает устаревшие результаты (иначе при быстром движении ползунка картинка «прыгала» бы назад).

**Загрузка** — по одному файлу: 20 снимков по 50 Мп параллельно — это гигабайты памяти. Оригинал после создания превью не хранится; экспорт перечитывает его с диска (`render_full`).

**Отмена экспорта.** Прервать чужую функцию снаружи нельзя, поэтому отмена срабатывает в колбэке `progress` (между страницами): он бросает `Cancelled`.

**Проверка:** `set QT_QPA_PLATFORM=offscreen` и `python scripts\ui_smoke.py` — загрузка, 4 фильтра, перетаскивание угла с лупой, перестановка, экспорт PDF/PNG, удаление.

## Этап 8. Сборка exe — `scaner.spec`

- **onedir** (папка), а не onefile: onefile при каждом запуске распаковывает ~200 МБ во временную папку — старт 5–10 с.
- `console=False` — без чёрного окна; `upx=False` — UPX ломает Qt-DLL и пугает антивирусы.
- Вырезаны ненужные DLL (~70 МБ): ffmpeg из OpenCV, программный OpenGL, Qt Quick/QML/PDF/Network. Итог ~240 МБ (основное — OpenCV 82 МБ, Qt, OpenBLAS из NumPy, x265 из pillow-heif для HEIC).
- Ленивые импорты (`core.export`, `core.ocr` внутри функций) PyInstaller находит сам — проверено `pyi-archive_viewer`.
- **Tesseract встроен** (`_internal/tesseract`, ~160 МБ до сжатия): `scripts/vendor_tesseract.py` копирует из установленной сборки UB Mannheim только `tesseract.exe` и DLL из его таблиц импорта (26 шт., считаются через `pefile`) — утилиты обучения моделей (~80 МБ) не нужны. Языки — стандартные `rus`/`eng` из tessdata. Переносимой копии нужен `TESSDATA_PREFIX`: путь к языкам зашит при компиляции (`core/ocr.py: _use_bundled_tessdata`).
- Список языков читаем сами (`tesseract --list-langs`), а не `pytesseract.get_languages`: тот декодирует вывод как UTF-8 и падает, если путь к tessdata содержит кириллицу.
- **Установщик** — Inno Setup (`installer/scaner.iss`): установка без прав администратора в `%LOCALAPPDATA%\Programs`, ярлыки, деинсталлятор, при обновлении старая `_internal` удаляется. Сжатие `lzma2/max` в отдельном процессе (ISCC 32-битный, `ultra64` ему не хватает памяти). 300 МБ → 122 МБ.
- Иконка (`assets/icon.ico`) — в exe, окне и установщике; свой AppUserModelID, чтобы панель задач показывала нашу иконку, а не python.

## Этап 7. Экспорт и OCR — `core/export.py`, `core/ocr.py`

- Страницы приходят **генератором** `render_full(p) for p in pages`: в памяти одна 50-Мп картинка, остальные уже сжаты в байты.
- PDF: `img2pdf` вставляет JPEG/PNG **без перекодирования**. Цвет/серый → JPEG q90; Ч/Б → 1-битный PNG (без потерь, в разы меньше).
- Размер страницы: DPI подбирается так, чтобы длинная сторона = 297 мм (A4). У фото нет настоящего DPI, без этого 50 Мп стали бы плакатом.
- PDF с текстом: Tesseract (`image_to_pdf_or_hocr`) делает одностраничный PDF с невидимым текстом поверх картинки → склейка через `pypdf`. Tesseract получает уже сжатый JPEG-файл, иначе встроил бы несжатый растр.
- Tesseract ищется в PATH и стандартных папках; при отсутствии — `TesseractStatus.message` с инструкцией по установке.

**Проверка:** `pytest tests/test_export.py tests/test_ocr.py` (тесты с настоящим OCR пропускаются, если Tesseract не установлен).
